# ChronoNote · 智能时间流记事与待办

> 一句话记下，自动落到时间轴上。本地优先、双击即开，多端通过 GitHub Gist 无损同步。

**在线使用：** https://l2036363518-lab.github.io/chrononote/

---

## 简介

ChronoNote 是一个**单文件网页应用** —— 全部代码在一个 `index.html` 里，没有构建步骤、没有后端、没有账号体系。

在一个输入框里写下：

```
明天下午3点 交周报 // 附上合同 https://a.com
```

它会自动拆成三样东西：标题「交周报」、时间「明天 15:00」、两条子备注（文字「附上合同」+ 链接 `a.com`）。

数据默认只存在**你自己浏览器的 IndexedDB** 里；需要跨设备时，接上自己的 GitHub Gist 做双向增量合并，不经过任何第三方服务器。

## 功能

### 1. 一个输入框完成录入

- 回车即发送，`Shift + 回车` 换行
- ` // `（空格 双斜杠 空格）之后的文字自动变成子备注；其中的 URL 自动识别为链接备注
- 输入框内 `Ctrl + V` 直接粘贴截图，自动压缩后作为图片备注
- 输入过程中实时显示时间属性胶囊，发送前可点击修改

### 2. 双引擎时间解析

| 引擎 | 触发方式 | 特点 |
|---|---|---|
| 本地正则 | 默认，实时 | 零延迟、零网络、完全离线可用 |
| DeepSeek AI | 点 ✨ 按钮 | 一句话里的多件事自动拆成多条任务，需要自备 API Key |

### 3. 四个视图，各归其位

- **今日计划**：今天要做的事（含跨天且仍在进行中的），加上还没清的**逾期**事项，按时间从早到晚排；顶部是完成进度条与「加到今天」快捷输入
- **时间轴**：明天 → 未来具体日期，按天分组；同一天内精确时间按 `00:00→23:59` 排序，全天事项排在其后
- **大致规划**：三天内 → 本周 → 下周 → 两周内 → 本月 → 下月 → 今年内 → 远期，共 8 档
- **琐事箱**：没有时间限制的杂事，按创建时间倒序

今天与逾期只出现在「今日计划」里，时间轴从明天开始 —— 同一条事项不会在一屏里出现两次。桌面端四栏并排（1024–1279 px 自动折成两行），手机端是四个分段。

### 4. 卡片交互

- **点标题或整行**：展开 / 收起备注，即时响应，没有等待
- **双击标题**或点工具栏的 **✏️**：改名（双击不会把备注来回开关两次，会还原成点击前的展开状态）
- 回车提交、Esc 取消，失焦也会提交；标题右侧的胶囊点开是改期菜单

### 5. 每日简报

当天第一次打开（且已过「提醒时间」，默认 08:00）时弹出一次：问候语、今日待办 / 已完成 / 逾期 / 近期规划四个数字，以及今日与逾期事项清单，可直接勾选完成。

- 「稍后提醒」＝ 30 分钟后再弹；「开始今天」＝ 当天不再弹
- 设置 → 每日简报：开关、提醒时间、「立即预览」与「今天再看一次」
- 关掉开关后完全不再自动弹出；每台设备各记各的「今天已看过」

### 6. 子备注

每个任务可挂载三类备注：文字（保留换行、可反复编辑）、链接（带域名胶囊、新标签页打开）、图片（自动压缩、网格缩略图、点开全屏灯箱）。

### 7. 跨端同步

GitHub Gist 双向增量合并：

1. 只在一边存在的任务，直接并入
2. 两边都有，按 `updatedAt` 保留更新的那份；同一毫秒再按 `updatedBy` / `updateId` 确定性取舍，保证两端算出同一结果
3. 删除是写 `deleted: true` 并刷新时间戳，所以删除也能同步，且不会在另一台设备上"复活"

合并完成后同时写回本地与云端；页面打开时会自动同步一次，本地改动后 8 秒也会静默推送一次（同步自身的写回已屏蔽，不会自触发循环）。

## 时间语法速查

| 你写的 | 解析成 |
|---|---|
| `明天下午3点半 交周报` | 明天 `15:30` |
| `后天中午12点 出发` | 后天 `12:00` |
| `本周三 评审` | 本周三，全天 |
| `下周一 例会` | 下周一，全天 |
| `11月8日 体检` / `2026-12-01 续费` | 对应日期，全天 |
| `11月3日 报销`（今天是 11 月 7 日） | **本月已过 → 记成 4 天前**，直接进「逾期未清」 |
| `9月1日 开学`（今天是 11 月 7 日） | 非本月且已过 → 明年的 9 月 1 日 |
| `9:30 站会` | `09:30`（今天已过则顺延到明天） |
| `今晚8点 跑步` / `明早7点 晨跑` | 今天 `20:00` / 明天 `07:00` |
| `明天下午2点到4点 开会` / `14:00-16:00 开会` | 当天区间 `14:00–16:00` |
| `3月5日到3月8日 出差` / `周一到周三 培训` | 跨天区间（卡片上标「至 3月8日 · 共 4 天」） |
| `明天9:00到18:00 值班` | 当天 `09:00–18:00` |
| `3天后 交初稿` / `2周后 复查` | 今天 +3 天 / +14 天，全天 |
| `2小时后 关火` / `半小时后 回电话` / `20分钟后 出门` | 从当前时刻起算的精确时间 |
| `三天内 交材料` | 三天内 |
| `两周内 体检` / `半个月内 修好打印机` | 两周内 |
| `下个月 交房租` | 下月 |
| `今年内 考完驾照` / `年底前` | 今年内 |
| `有空 整理照片` / `近期` / `改天` | 远期 |
| `买洗衣液` | 琐事箱（无日期） |

> 数字口语也认：`下午两点半`、`晚上八点`、`十一`、`二十一`。
>
> 区间用「到 / 至 / ~ / —」连接，或直接写 `14:00-16:00`。改期时跨天区间的结束日会按同样天数平移。
>
> **`X月X日` 的年份规则**：本月内已经过去的日子按**今年**算（补记上周的报销，记的是那天，不是明年）；其它月份按「最近的将来」算，避免把远期安排记成历史。带年份的 `2026-12-01` 永远按写的来。

## 数据与隐私

- **任务与图片**：存在浏览器的 IndexedDB（localforage），不经过任何服务器
- **配置项**：`deepseekApiKey`、`githubToken`、`gistId`、`lastIsoWeek` 四项，以及每日简报的 `briefEnabled` / `briefTime` / `briefLast` / `briefSnooze`，都存在 localStorage
- **同步**：只写到你自己账号下的私密 Gist，本应用没有任何中转服务
- **注意**：GitHub 的 secret gist 只是"不被搜索到"，不是加密；拿到链接的人可以读取，别存放密码等敏感信息
- 已删除的事项只保留墓碑（去掉图片）；所有已知设备都在这次删除之后同步过时，墓碑会被**自动回收**（设备登记在 Gist 的 `devices` 字段，180 天未出现的设备自动剔除）。想立刻收缩体积可在 设置 → 数据 → **清理删除标记** 手动清除
- 密钥只存在本机 localStorage，任何能运行本页脚本的第三方代码都可能读取；公用设备用完可点 设置 → 数据 → **清除本机密钥**
- 云端 `schema` 高于本端时**熔断同步**，避免旧客户端把新字段洗掉；未知字段在保存时会原样保留
- 日期与时间做真实日历校验：`2026-02-31`、`25:90` 这类非法值在解析、导入、改期三层都会被拒绝
- 本地存储异常（读库失败、记录无法识别）时会显示顶部横幅并**暂停自动保存与云同步**，避免用残缺数据覆盖云端

想清空本地数据：设置 → 数据 → 清空全部。

## 快速开始

**直接用：** 打开 https://l2036363518-lab.github.io/chrononote/

**离线用：** 下载 `index.html`，双击即可（首次加载需要联网取 CDN 依赖）

**装到手机桌面（安卓）：**

1. 用 **Chrome** 打开上面的网址（必须是 https，微信内置浏览器不行）
2. 右上角 ⋮ → **安装应用**
3. 装完是一个独立窗口：没有地址栏、托盘有独立图标、断网也能打开

装不上时按这个顺序排查（都是实测踩过的坑）：

| 现象 | 原因 | 处理 |
|---|---|---|
| 点安装后一直停在「正在安装」，应用列表也搜不到 | 系统拦截了 APK 安装，国产 ROM 很常见 | 设置 → 应用 → **Chrome** → **安装未知应用 → 允许**，再装一次（**最常见的拦路虎**） |
| 同上，华为 / 荣耀机型 | **纯净模式**拦截 | 设置 → 系统和更新 → 纯净模式 → 关闭 |
| ⋮ 里只有「添加到主屏幕」，没有「安装应用」 | 页面是旧缓存，manifest 没挂载 | 设置 → 关于 → 看「清单文件」是否为 **已挂载**；不是就点「强制刷新」 |
| 权限都开了仍失败 | WebAPK 铸包依赖 Google 服务器，部分网络不可达 | 改用 `?plain=1` 走本地快捷方式（见下） |

> **备用方案（不需要任何权限）**：把网址末尾加上 `?plain=1` 打开 —— `https://l2036363518-lab.github.io/chrononote/?plain=1` —— 此时页面不加载 manifest，Chrome 会改给「添加到主屏幕」，本地生成快捷方式，不联网也能装。功能与安装版完全一致（含离线缓存），区别只是顶部多一条地址栏。

> iPhone 上 Chrome 没有这个功能，请用 **Safari** 打开 → 分享 → 添加到主屏幕（可全屏运行）。

**开同步：**

1. 到 [github.com/settings/tokens](https://github.com/settings/tokens) 创建 **classic** token，只勾 `gist` 一项（fine-grained token 不支持 Gist）
2. 应用内 设置 → 跨端同步 → 填 Token，Gist ID 留空 → 点「立即同步」，会自动创建 Gist 并回填 ID
3. 其他设备填**同一个 Token + 同一个 Gist ID**

## 更新部署

本仓库即站点源：

1. 用新的 `index.html` 覆盖仓库里的同名文件（`Add file → Upload files`）
2. PWA 相关文件首次部署时需要一并上传：`manifest.webmanifest`、`sw.js`、`icons/`（否则安卓只能生成书签，不能安装）
3. **每次发版都把 `sw.js` 里的 `CACHE` 改成新版本号**（如 `chrononote-v1.7.5`）：应用靠“`sw.js` 字节变了”判断有没有新版；只换 `index.html` 而不动 `sw.js` 时，这条线索就失效了（还能靠 `Last-Modified`，但不保证每个托管方都给）
4. Settings → Pages 已配置为 `main` / `root`，提交后约 1 分钟自动重建
5. 各端刷新页面即生效（Service Worker 对页面走网络优先，新版本刷新即可拿到）

## 已知限制

- 首次打开需联网加载 CDN 依赖；断网后依赖浏览器缓存
- 已内置 manifest 与 Service Worker：安卓 Chrome 可「安装应用」（独立窗口 + 独立图标），装过一次后断网也能打开；iOS 加主屏可全屏运行
- 首次安装那一次必须联网（要从 CDN 取 Vue / LocalForage 等依赖），之后由 Service Worker 缓存接管
- 同步在页面打开时自动执行一次，本地改动后 8 秒自动推送；想看即时状态可手动点「立即同步」
- AI 拆解依赖 DeepSeek API，Key 与网络均需自备
- **同步是整条记录级别的“后写者胜”**：同一任务在两台设备上分别改了标题和日期，最终只保留写得更晚的那一版，另一端的字段改动会丢。字段级合并要给每个字段单独记时间戳，属于数据格式变更，尚未做
- **Gist 没有条件写入**（不支持 `If-Match`）：PATCH 前会二次读取并重新合并，把并发窗口压到毫秒级，但两台设备**同时**提交仍可能互相覆盖。跨端请避免同一时刻编辑同一条
- **逾期按日期判定，不按当天时刻**：今天 09:00 的事到下午还没勾，不会标「已过期」（`targetTime` 是日程时间，不是截止时间）；跨天任务要等整个区间过去才算逾期
- **删除参与“后写者胜”**：设备 A 删掉一条、设备 B 之后离线改了它（`updatedAt` 更大），B 的版本会赢，任务重新出现。这是 LWW 的定义行为——改成“删除永远赢”会静默吞掉 B 的修改，所以没有这么做
- **「清理删除标记」会真的删掉云端记录**：之后某台长期离线、本地还留着旧副本的设备再同步，可能把它带回来。所有设备都正常同步过之后再清理才安全（确认框里也写了这句）
- **没有时区模型**：`targetDate` / `targetTime` 是**本地日期时间**，不记录创建时的时区。两台设备处在不同时区时，同一条会被各自按本地时间理解；`completedAt` 的“今天”也按本机时区计算
- **密钥明文存在 localStorage**：单文件、无后端的架构下，DeepSeek Key 与 GitHub Token 只能放在本机存储里，任何能运行本页脚本的第三方代码都可能读取。公用设备用完请点 设置 → 数据 → 清除本机密钥；不要在有不明插件的页面里保存密钥
- **更新提示依赖 `Last-Modified` 或 Service Worker 字节比对**：两者都拿不到时会明确提示「无法检查更新」，不会谎称已是最新；极端慢网下更新等待有 5 秒兜底，可能仍需再刷一次
- **老数据的完成时间是推算的**：升级前就已完成、且没有 `completedAt` 的记录，按当时的 `updatedAt` 迁移一次；如果那条在升级前刚被编辑过，推算出的“完成时刻”会是编辑时间
- **云端有坏记录时同步只拉不推**：Gist 里存在规范化不了的条目时，这次同步不会回写（否则会把它们抹掉），状态栏会说明「只拉取、未推送」；修好云端数据后自动恢复

## 版本

当前 `v1.7.9`

- v1.7.9：**落盘改成 IndexedDB 事务式“读-合并-写”**——同一对象仓库的 readwrite 事务跨标签页串行执行，两页同时保存也不会互相覆盖（localforage 只在非 IndexedDB 驱动时兜底，有 `navigator.locks` 时再套一层锁）；落盘排队执行、返回成败，**同步前先落盘，落盘失败就停止推送**。**物理清理的 id 长期记住**（`chronoPurgedLocalIds`）——即使云端补推成功，旧标签页/离线设备也写不回墓碑；加载、同步、拉取、落盘四处统一走 `excludePurgedTombstones`。**草稿图片改为 `{id, src}` 对象**：AI 请求期间按 id 摘除“请求前那批图”（原来按字符串比较，同图重贴会误删）。`sameTasks` 增加 `updatedBy`/`updateId`/全文比较，同毫秒冲突也能识别
- v1.7.8：**多标签页机制重做**——v1.7.7 的广播-拉取链路会形成无限写库循环（每个标签页收到“变了”就重赋值、重落盘、再广播）。现在①内容没变就不赋值不落盘（`sameTasks` 收敛检查，实测广播数收敛到 4/3 后不再增长，去掉该检查会持续增长）；②本页没未落盘改动时**直接采用磁盘内容**，物理删除/清空因此能真正传播到别的标签页（原来 merge 只做并集，删不掉）；③本页落盘前先读后合并再写，两边同时改也不会互相覆盖；④刚清掉的墓碑不会从“还没写入的旧库”里合并回来。另外：连续清理删除标记会**合并**待补推列表（原来第二次清理会把第一次没推成功的 id 顶掉）；AI 请求期间新贴的图片不再挂到生成的任务上、也不会残留重复
- v1.7.7：**修复 AI 批量建任务撞 id**（v1.7.6 回归）——`stableIdOf` 只用于「云端/导入里缺 id 的记录」，本地新建一律走 `uid()`；同一份数据里若仍算出重复 id，按出现顺序加确定性后缀，不再被合并成一条。**清理墓碑更稳**——改成记录「本次清掉了哪些 id」并持久化：只滤这些 id（别的设备刚删的墓碑不受影响），推送失败时保留待补推列表，下次同步自动补上；同步在跑时点清理会先提示而不是白清。**非法日期/时间也计入“会被改写”**，这类云端数据同样只拉不推。**只拉未推时同步条显示「只拉未推」**（红色），不再显示成“已同步”。**AI 请求期间打的字不会被清掉**（只清请求发出时的那份草稿）。**多标签页协调**——用 `BroadcastChannel` 广播改动，其他标签页从库里重新合并，避免一个页面的旧数组盖掉另一个页面新增的任务
